# GoreeCloud Contacts — native Linux application

An original GTK4/libadwaita Linux desktop Contacts app, not a web wrapper. It uses its own private SQLite database, never Android Contacts Provider data, browser IndexedDB or CardDAV servers.

Runtime: GTK4, libadwaita 1, GObject Introspection (python3-gi, gir1.2-gtk-4.0, gir1.2-adw-1 on compatible Debian/Ubuntu), Python >= 3.11. Run from repository root:
  PYTHONPATH=linux /usr/bin/python3 -m goreecloud_contacts.app

Optional guarded per-user installation (explicit execution, no root, no personal contact transfer):
  python3 linux/install_user.py

It creates a launcher in ~/.local/bin, a desktop entry in ~/.local/share/applications and application code in ~/.local/share/goreecloud/contacts-linux, honoring XDG overrides. Refuses existing installation paths; private launcher/desktop entries use exclusive creation, file-sync before success, and incomplete-write cleanup on failure. Installer rollback touches only newly created application files, not personal Contacts SQLite; no automatic replacement/updater is provided. Private contact data lives separately under ~/.local/share/goreecloud/contacts (0700 dir, 0600 SQLite). Exports are exclusive create-only 0600 files; failed disk flushes and user interruptions remove newly created incomplete files rather than leaving corrupted private exports (if cleanup fails, the operator must inspect the destination). Existing filenames and symlinks are never overwritten. There is no encryption at rest.

Implemented in source: native list/search/favorites, readable per-row favorite labels and keyboard-operable toggle actions, editor, user-confirmed delete, explicit JSON and limited vCard import, private JSON backup and limited vCard export. Native GTK manual exports provide a separate Export favorites only checkbox (default off); confirmation discloses a validated snapshot scope and count. Search/Favorites display filtering never silently scopes export; empty favorites-only export refuses a file. Rich vCard properties are rejected and favorite markers cannot be restored from vCards. OS file chooser and native toasts use existing verified GC UI roles. Neither CardDAV sync nor a deployed backend is included.

Tests: PYTHONPATH=linux /usr/bin/python3 -m unittest discover -s linux/tests -p test_*.py; PYTHONPATH=linux xvfb-run -a /usr/bin/python3 linux/tests/gtk_smoke.py. A separate synthetic installed-launcher smoke checks the actual per-user XDG launcher, SQLite privacy modes, persistence after restart, and package assets: PYTHONPATH=linux /usr/bin/python3 linux/tests/installed_smoke.py. This test uses Xvfb and a disposable profile with denied desktop-portal D-Bus access; it never installs to ~/.local or opens personal contacts.

CLI manual JSON/vCard exports now offer explicit --favorites-only scope without changing the default all-contacts export, plaintext consent, exclusive file creation or limited vCard fields. An offline, non-networked command-line companion is now available from the same local source and private SQLite store: PYTHONPATH=linux /usr/bin/python3 -m goreecloud_contacts.cli status. The opt-in user installer also creates a distinct executable ~/.local/bin/goreecloud-contacts-cli. CLI exports require --acknowledge-plaintext; imports require --yes and vCard imports additionally require --accept-limited-fields. Commands report only counts and general errors by default, validate untrusted files before opening SQLite, do not overwrite existing backup filenames and have no credentials, synchronization or telemetry. Offline `preflight-restore` and `preflight-vcard` check import capacity and conflicting IDs/details without importing, opening an existing database read-only and leaving a missing database uncreated. Actual imports recheck every condition under the write lock. See [CLI guide](CLI.md).

Physical Linux installation/removal/upgrade acceptance, accessibility tests, signing and Stable release gate remain open. See docs/PLATFORMS.md in the parent repository.
