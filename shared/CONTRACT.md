# Portable GoreeCloud Contacts contract — version 1

The manual export/import contract shared by the web and Linux development clients is goreecloud.contacts.v1. It is NOT a network API and does not change Android's permission-gated system Contacts Provider.

Each contact contains exactly six fields: id (lowercase UUIDv4), name (required UTF-8 string), phone (optional single string), email (optional single string), organization (optional single string), and favorite (boolean). Unicode codepoint maximums: name 160, phone 80, email 254, organization 160. UTF-8 byte maximums are four times these values. Strings are trimmed and NFC-normalized. Control characters, bidi directional overrides/isolation/format marks, Unicode line separators and invalid Unicode are rejected. The JSON bundle contains exactly format and contacts.

Maximum: 5,000 records and 2 MiB UTF-8 JSON size. Duplicate IDs within one backup are rejected; new imports are single atomic transactions and refuse existing-ID conflicts. Browser IndexedDB and native Linux SQLite edit/delete operations compare the original contact snapshot with the current stored row and fail closed on a stale concurrent change, rather than silently overwriting edits made in another tab or app instance. No contact identifiers are automatically tied to Android system contacts, CardDAV resource UIDs or a remote account. Portable backups preserve favorites; limited vCard 3.0 exports contain only FN/N/TEL/EMAIL/ORG and omit favorites, notes, photos, addresses, groups and other rich details.

Synthetic example: fixtures/contacts-v1.json. Cross-language tests require Python Linux and JavaScript web serializers to emit byte-identical JSON and vCard for this example. Both output formats are unencrypted and require explicit user-directed export. Unknown schema fields are rejected, not silently dropped. External arbitrary address books are not supported by the JSON importer.

Any future schema change requires explicit versioning, rollback, data migration and security review. Any future CardDAV/Mesh adapter must include permissioned Identity integration, GoreeShield user consent and Wardveil controls; local manual file transfer is not permission to auto-sync.
